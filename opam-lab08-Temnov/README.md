Параметри варіанта

- **Порівняння:** `string.CompareTo`
- **Шукані елементи:** X = "О-00", Y = "О-99", Відсутній = "Я-99"
- **Запит межі (b = 1):** індекс останнього входження X
- **Варіант пошуку (c = 0):** Рекурсивний бінарний пошук

---

Завдання 1. Лінійний пошук
- **X ("О-00"):** 56124 порівнянь
- **Перший:** 1 порівняння
- **Відсутній ("Я-99"):** 100000 порівнянь

Пояснення: Третій запит є найдорожчим, оскільки лінійний пошук повинен перевірити абсолютно всі елементи масиву до самого кінця, щоб підтвердити відсутність шуканого значення.

---

 Завдання 2. Бінарний пошук і 4 поломки
1. `while (lo < hi)`: Елемент не знаходиться, коли він лишається єдиним на позиції `lo == hi`.
2. `lo = mid`: Цикл зависає, коли `hi - lo == 1`, оскільки значення `mid` більше не змінюється.
3. `mid = (lo + hi) / 2`: На розмірі 100 000 працює нормально, бо сума індексів не перевищує `int.MaxValue`.
4. Невідсортований масив: З 100 запитів близько 90% наявних елементів не знайдено (-1).

---

Завдання 3. Пошук межі
- **LowerBound:** 17 порівнянь
- **UpperBound:** 17 порівнянь
- **Індекс останнього входження X (b = 1):** `UpperBound - 1`
- **Кількість елементів = X:** `UpperBound - LowerBound`

Пояснення: Кількість порівнянь не залежить від кількості X, адже бінарний пошук завжди ділить навпіл увесь проміжок індексів до 1 елемента ($\lceil \log_2 N \rceil$ кроків).

---

Завдання 4. Рекурсивний бінарний пошук
- **Глибина рекурсії:** 17
- **Чи загрожує StackOverflowException:** Ні, оскільки глибина складає всього ~17 викликів для 100 000 елементів, а стек C# розрахований на тисячі викликів.
